# GitHub 与 Gitea 同步和发布

## 约定

GitHub 为源码及 Wiki 主仓库，Gitea 为同步副本和程序主下载源。不要两边同时编辑同一内容。脚本默认只检查，必须显式传 -Apply 才写远端；不删除远端内容，不强推，不移动已有标签，不修改历史 Release。

依赖：Git、Python 3、requests（`python -m pip install requests`）。凭据使用本机 Git Credential Manager；可选 GITHUB_TOKEN / GITEA_TOKEN 环境变量仅供 API 使用，Git 推送仍需 Git 凭据。不要将令牌写入脚本或提交配置。两站 API 令牌必须具有对应仓库写入权限。

## 同步源码、标签、Wiki

在项目根目录运行：

```powershell
# 只检查（当前有一个已知历史标签冲突）
.\tools\Sync-Repositories.ps1 -SkipTag v18.30-Meme.v009
# 执行并回读验证
.\tools\Sync-Repositories.ps1 -Apply -SkipTag v18.30-Meme.v009
# 只处理 Git，不访问 Wiki API
.\tools\Sync-Repositories.ps1 -Apply -GitOnly -SkipTag v18.30-Meme.v009
```

未明确跳过的同名标签冲突、分支不能快进时停止，不自动合并。先在工作区人工核对并正常合并，再执行。目标独有标签保留，不复制回 GitHub。Wiki 通过 Gitea API 按页面同步，保留目标额外页面；同名页面以 GitHub 为准。Wiki 内容一致，不要求两站 Wiki 的提交历史一致。

## 今后的双站发行

先完成构建与验收，确保 AHK CurrentVersion 与新标签一致，并把同一标签推到两边。此脚本不会自动创建标签或编译程序。源码文件必须与本地标签中的同名文件内容一致。EXE 应来自该次已验证的构建。

```powershell
# 仅预检；以下路径和版本是示例，请替换为实际新版本
.\tools\Publish-Release.ps1 -Version v19.00-Amiya.v009 -Exe .\dist\Kedit.exe -Source .\Kedit_GO_to_Def.ahk -NotesFile .\release-notes.md
# 创建两站草稿，上传并完整回读所有附件校验 SHA-256
.\tools\Publish-Release.ps1 -Version v19.00-Amiya.v009 -Exe .\dist\Kedit.exe -Source .\Kedit_GO_to_Def.ahk -NotesFile .\release-notes.md -Apply
# 确认两个草稿后，复用已验证的附件并公开发行
.\tools\Publish-Release.ps1 -Version v19.00-Amiya.v009 -Exe .\dist\Kedit.exe -Source .\Kedit_GO_to_Def.ahk -NotesFile .\release-notes.md -Apply -Publish
```

发布附件：固定名 EXE、版本化 EXE、版本化 AHK、固定名 EXE.sha256。两份 EXE 使用同一个本地文件。说明不同、同名附件大小或哈希不同、发行类型不同会停止，不自动替换。未上传成功的部分可以重试；已有正确附件跳过。已公开但缺附件的版本需要人工检查，不自动修补。

两站附件均验证完成后才开始公开，先 Gitea 再 GitHub；跨站发布不能原子完成，第二站失败时第一站可能已公开。保留终端错误并重试，不能将单站成功当作两站成功。回读校验会再次下载附件，需要相应流量；预检已有资产也会校验它们。

不要同时运行多份发布脚本。本轮只验证安全逻辑与预检，不创建新发行；真实新版本首次发布仍需核对权限、草稿和附件上传结果。
